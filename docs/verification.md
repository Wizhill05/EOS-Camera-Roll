# Verification for 0.6.3

The user reported the previous Camera roll app working well on the physical EOS R50 V. This redesign has not been installed or driven on that physical handset by the build environment.

Version 0.6.3 removes the silent sequential video spool: a camera response that ignores Range is rejected without reading its body. The old spool downloaded a complete video while MP4 preparation could wait for its tail, and synchronous stream/player cleanup could block the UI. Streaming now requires exact validated ranges, with a bounded cache, startup byte/time limits, short socket timeouts and a progress watchdog. Cancellation marks the source closed immediately and disconnects in the background; native player release also runs outside the UI thread. Explicit Download & play saves into the user's chosen folder and then opens the local document, with an external-player option for unsupported codecs.

Video viewers no longer make competing thumbnail or information requests. Photo preview requests use an isolated cancellable session, so a closed/replaced preview cannot follow up with an original download. The previous thumbnail-only browsing protections remain in place. The gallery now uses three square columns with 6dp corners in both themes.

The current checks exercise:

- Thirty-two Android API 34 Robolectric workflows: native dark/light three-column square screens; full-resolution JPEG viewer and ratings; selected/save state; persistent ratings and filtering; read-only Lightroom original staging and traversal/mode rejection; restored camera libraries; unreachable refresh preserving cached photos; connected empty cards; portrait orientation from small camera rotation metadata when the thumbnail omits EXIF; offline loading of that normalized thumbnail without camera requests; invalidation of stale orientation after thumbnail eviction and a changed file revision; foreign-origin snapshot rejection; exact document-provider original bytes; completion/failure notifications; cleanup of failed writes; creation of card-copy directories; duplicate-save receipt reuse; ignored video ranges failing with no automatic retry while the next gallery thumbnail still loads; MediaPlayer errors and stale callbacks; stalled startup watchdog; background playback cleanup; lost video surfaces cancelling the source without a duplicate stream; offline saved-video playback and read grants to an external player; explicit download-to-folder followed by local video playback; cancellation of an old photo preview without follow-up original requests. MediaPlayer is simulated for these lifecycle tests; no codec decoding is established.
- Ten gallery traffic/connection checks among those Android workflows: four cold fixture tiles produce four small thumbnail GETs, zero original GETs, zero display-image GETs, at most one active gallery request and only one metadata probe when that camera format omits rotation; refresh/rebind/restart reuse cached thumbnails without another request; recycled queued jobs do not reach the camera; a rebound holder receives its pending image; a burst of stale bindings cannot crowd out the new visible tile; the queue stays bounded; pause/resume preserves new work; a thumbnail is visible before gated metadata completes; opening a photo learns missing rotation and updates its cache; a real activity scan/layout of 40 fixture files requests only the current gallery area's thumbnails, never original images.
- Twenty host protocol checks, seven link-parser checks, and fifty media/orientation/error checks. Includes paginated CR3/XFVC coverage, >4 GiB video offsets, original-byte/hash fidelity, cancellation, EXIF/CMT1 orientation parsing, double-rotation prevention and distinct network/account/device error classes. Video regressions verify refusal of full-response bodies, bounded pre-frame reads, header/tail block reuse, nonblocking close during a stalled response, termination of cancelled reads and no new camera requests after close.
- Android release assembly and lint. Lint warnings remain for English-only strings, RTL alignment, platform ExifInterface, explicit durable preference commits, target API age and manifest attributes.
- Signature compatibility with the earlier app. Certificate SHA-256: `4f6d16a083d3fafbf827b2f5de1461eb0de63b28a77934f30d82cd8cddcb8c80`.

Screenshots are software renders of native Android views under Robolectric. They do not prove handset GPU, system file-provider, video-codec or Adobe app behavior. The photo fixture derives from the public-domain EOS R50 V RAW at https://raw.pixls.us/getfile.php/8403/nice/Canon%20-%20EOS%20R50%20V%20-%20RAW%20%283%3A2%29.CR3. Published source hash: `955ff98710505498ce7f98cbcc5875793ef2d6941b3b5692ed3baf2817ee7c9f`. It was rendered at 6048 × 4020 using the pinned LibRaw source, then cropped into test-only thumbnail variations. If that sample is unavailable during a clean test build, the layout test uses generated bitmap fixtures instead. Test photos are not bundled as user media in the app.

Still requires physical-device checking: this gallery's touch/scroll behavior; orientation on the user's own camera files; camera reconnection through the live hotspot; background service behavior under the phone vendor; ARM64 RAW memory/performance; video codecs and seeking; actual Lightroom import/cleanup. A fixture-based portrait test is not evidence that the user's exact files have been examined.

The traffic assertions measure requested paths, response usage and request counts against a local camera fixture. They are not a claimed handset speed multiplier or Wi-Fi throughput benchmark. The physical Canon/phone network must still be retested. The deleted original-header operation’s old checks were removed; original transfer origin confinement and metadata parsing remain covered.
