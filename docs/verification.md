# Verification for 0.6.5

37 Robolectric Android workflows exercise paired RAW/JPEG representatives, format-specific views, fixed viewer toggles, camera versus phone-only ratings, original EXIF exposure extraction, grouped saved marks, ISO filtering and native dark/light filter renders, plus the existing traffic, no-playback, restore, transfer and Lightroom checks.

81 host checks cover protocols, links and media. New checks cover same-folder pairing and bulk expansion, advertised write capability, rejection of unadvertised writes, successful and ignored rating writes, clearing ratings, and authenticated PUT/readback. The fixture closes its HTTP responses explicitly. These are protocol fixtures, not a physical-camera write test.

The ARM64 LibRaw JNI library was rebuilt with the pinned NDK. The public R50 V sample described below rendered at 6048×4020 and exposed ISO 100, shutter 0.001 s, aperture 2.8, focal length 28 mm and RF28mm F2.8 STM. New JNI metadata reads only the already-local RAW file and does not unpack or download another original. This host check and Android compilation do not establish handset runtime performance.

Release assembly, lint, actual APK no-playback inspection, original signing certificate, package/version and 16 KiB ZIP alignment are checked. Camera rating changes require advertised capability and matching readback; support on the user's physical R50 V remains unverified. No camera rating is labelled confirmed based solely on the local tap or HTTP success. Camera/phone failures retain the local rating and report unconfirmed synchronization.

The 0.6.4 network precautions remain: one client per camera origin through cleanup, bounded small responses, failure-triggered background stop, no video player, no original-header grid probes and zero-network cache reuse. Cold visible photos now read small rating metadata even if rotation is absent.

Screenshots are software renders of native Android views under Robolectric. They do not prove handset GPU, system file-provider, video-codec or Adobe app behavior. The photo fixture derives from the public-domain EOS R50 V RAW at https://raw.pixls.us/getfile.php/8403/nice/Canon%20-%20EOS%20R50%20V%20-%20RAW%20%283%3A2%29.CR3. Published source hash: `955ff98710505498ce7f98cbcc5875793ef2d6941b3b5692ed3baf2817ee7c9f`. It was rendered at 6048 × 4020 using the pinned LibRaw source, then cropped into test-only thumbnail variations. If that sample is unavailable during a clean test build, the layout test uses generated bitmap fixtures instead. Test photos are not bundled as user media in the app.

Still requires physical-device checking: this gallery's touch/scroll behavior; orientation on the user's own camera files; camera reconnection through the live hotspot; background service behavior under the phone vendor; ARM64 RAW memory/performance; physical video original transfers and camera recovery; actual Lightroom import/cleanup. A fixture-based portrait test is not evidence that the user's exact files have been examined.

The traffic assertions measure requested paths, response usage and request counts against a local camera fixture. They are not a claimed handset speed multiplier or Wi-Fi throughput benchmark. The physical Canon/phone network must still be retested. The deleted original-header operation’s old checks were removed; original transfer origin confinement and metadata parsing remain covered.
