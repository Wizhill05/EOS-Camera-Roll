Remove video playback after continued physical-camera connection lockups on 0.6.3.

- Delete the player, remote-video source, range requests, seek controls, Download & play, autoplay and external-player actions. Videos retain thumbnails, local ratings and explicit Save.
- Serialize HTTP clients to the same camera through response cleanup. Do not start a replacement request while a cancelled response is still closing.
- Let small thumbnail responses finish when entering the viewer. Remove eager file-information requests and repeated pause cancellations.
- Bound small responses by size and time. Stop automatic thumbnails after the first connection failure and stop folder scans after transport loss. Preserve cached media for manual refresh.
- Preserve sequential original downloads, progress, save receipts, ratings, Lightroom photo handoff and the three-column square gallery.
- Add a release APK inspection check that rejects playback code and executable HTTP Range constants. It rejects the previous 0.6.3 APK.

Install over the existing app. An already-stuck camera may need its CCAPI connection restarted once before it is reachable. Client cancellation cannot reset an unresponsive camera service.

Validation: release build and lint, 30 simulated Android workflows, 71 host checks and actual APK inspection. Physical R50 V recovery has not been verified by the build environment. The exact camera-side failure remains unconfirmed. See [the investigation](https://github.com/Wizhill05/EOS-Camera-Roll/blob/main/docs/network-lockup.md).
